# Robust Strategies for the 100-Day System
These are battle-tested rules. Follow them strictly.

---

## 1. Energy & Schedule Protection

- The 6:00–8:30 PM block is non-negotiable. Treat it like a client meeting.
- Research hour (11:30–12:30) is reading + notes only. No coding. No LinkedIn.
- If you are exhausted after 1:00 AM more than twice in a week → stop at 1:00 AM. Sleep is part of the system.
- Never move the learning block to later “just this once”. It breaks the habit.

## 2. One Focus Rule

- Learning block = one main concept + one hands-on task.
- Research block = one paper/article + notes.
- If you feel the urge to jump topics, write the idea in `Content-Ideas.md` and stay on the current task.

## 3. Output Mandatory Rule

Every single day must produce visible output:
- Learning day → working code or clear notes
- Research day → written takeaway
- Weekend → public repo or demo

No output = the day did not count.

## 4. Progressive Difficulty

- Days 1–14: Follow the daily checklist exactly. Do not improvise.
- Days 15–35: You may adjust order slightly inside the phase, but finish every required outcome.
- Days 36+: You have more freedom, but still hit the phase checkpoints.

## 5. Missed Day Protocol

1. Do not try to “catch up” by doing two days in one.
2. Mark the missed day in `.\Notes\PROGRESS.md`.
3. Continue with the next scheduled day.
4. If you miss 3+ days in a week → do a short Sunday recovery plan (max 3 hours).

## 6. Weekly Shipping Rule

Every weekend must end with at least one of:
- Public GitHub repo with clean README
- Working demo (Loom or screenshots)
- Detailed technical write-up

This is the highest-leverage activity in the entire system.

## 7. Content Capture Discipline

- Keep `Content-Ideas.md` open during both learning and research blocks.
- Any time you think “this would make a good post” → drop one line immediately.
- At 8:45 PM you only write. You do not invent ideas from scratch.

## 8. Review Cadence

| When | Duration | Action |
|------|----------|--------|
| End of every learning block | 5 min | Write tomorrow’s one-sentence goal |
| Friday night | 15 min | Update `.\Notes\PROGRESS.md` |
| Sunday night | 20–25 min | Full weekly review + adjust next week |

## 9. Quality Over Speed

- Better to deeply understand one concept than to rush three.
- If a concept feels fuzzy after the hands-on task → spend the next learning block on it again. Do not force progress.

## 10. Definition of Done (Daily)

A day is complete only when:
- [ ] Learning block finished with output
- [ ] Research notes + one-sentence takeaway written
- [ ] Code committed (if any was written)
- [ ] Content idea captured (if any appeared)
- [ ] Tomorrow’s focus written

**These strategies override everything else.**
